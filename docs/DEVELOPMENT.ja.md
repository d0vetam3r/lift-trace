このリポジトリと `lift-trace-source-<version>.zip` がWindowsアプリのソースです。実行ファイルの配布版は別の製品ではなく、同じアプリにランタイムを同梱し、開発環境なしで使えるようにしたものです。

## ソースから実行する

必要なツールと環境：

- **Python 3.10以降**。デスクトップ管理ウィンドウはTkinterを使用します。通常のWindows用Pythonインストーラーに含まれています。
- **Node.js 18以降**。JavaScriptのテストにのみ必要です。
- ネイティブのコントローラー入力とOBSの自動起動にはWindowsが必要です。手動で連携を確認する場合はOBS Studioも必要です。

既存のコントローラー入力と手動OBSオーバーレイには、追加のPython・npmパッケージは不要です。任意の自動表示をソースから使う場合は、先に `python -m pip install -r requirements-automation.txt` で `websocket-client==1.9.2` と `Pillow==12.3.0` をインストールします。これらがなくても通常の入力と手動オーバーレイは使えます。Windowsアプリのビルドには同梱するため、一般ユーザーにはインストールコマンドを要求しません。ソースのルートフォルダーで実行します。

```sh
python desktop.py
```

Windowsアプリと同じデスクトップ管理ウィンドウと、ブラウザーの設定画面が開きます。サーバーだけを実行する場合は次のコマンドを使います。

```sh
python server.py
```

その後、`http://127.0.0.1:8765/` を開きます。この方法で起動したサーバーはCtrl+Cで終了します。`start.bat` はソース利用者向けの補助として残しており、一般ユーザー向けのインストール手順では使いません。macOS/Linuxでは `bash start.sh` でデモと、設定ページにフォーカスがある間のキーボード入力を利用できます。これらの環境ではネイティブのコントローラー入力とOBSの自動起動には対応していません。

配布する実行ファイルには、OBSの補助スクリプトが使う、ウィンドウを表示しないサーバーモードがあります。ソースからは次のように実行します。

```sh
python desktop.py --serve --port 8765 --data-dir data
```

既存の設定から分離して確認する場合は、書き込み可能な `--data-dir` を指定してください。管理ウィンドウは `--language en`、`--language ko`、`--language ja` に対応し、設定ページでは `?lang=en`、`?lang=ko`、`?lang=ja` を指定できます。

## テスト

```sh
python -m unittest discover -s tests -p "test_*.py" -v
node --test tests/engine.test.mjs tests/client.test.mjs tests/render.test.mjs tests/i18n.test.mjs tests/setup.test.mjs tests/automation.test.mjs
```

一部のPythonテストは、ループバックアドレスで一時的に接続を待ち受けます。制限のある実行環境では、これを許可する必要があります。テストは合成入力を使うためコントローラーは不要ですが、実機の互換性やゲームキャプチャとの同期は確認できません。

`.github/workflows/verify.yml` はWindowsとUbuntuで、Python 3.10/3.13およびNode 22を使って検査します。記録されている2026-10-12のpush実行では、4通りすべてに合格しました。対象コミットと実行記録は[検証状況](VALIDATION.ja.md)を参照してください。複数のOSでテストに合格しても、Windows以外でネイティブのコントローラー入力に対応したことにはなりません。手動実行のワークフローは、固定されたランタイムの準備、出所確認を含むWindowsアプリのビルド、基本動作の検査、Actionsアーティファクトへのアップロードを行います。リリースは公開しません。記録されているpush実行では、このWindowsビルドジョブはスキップされています。

## 任意のINFINITAS自動表示

現在の開発ソースには、ローカルOBS WebSocket接続、対象選択UI、SCORE領域の判別器が接続されています。公開版v0.1.0には含まれておらず、新しいリリースを公開した変更でもありません。設定手順は[使い方](USER_GUIDE.ja.md#任意infinitas自動表示未リリース)を参照してください。INFINITASの画面・速度・配置の計算は`web/games/infinitas.js`にあり、既存の設定・関数名・計算結果は維持しています。

最初の画面プロファイルは、拡縮していない1920 × 1080の元ソース内のSCORE領域 `(170, 953, 90, 20)` だけを比較します。利用者がプレイUIから基準を保存して使います。曲開始前のプレイUIも検出するため、譜面が流れる時間だけを判別する機能ではなく、任意のスキンや解像度には対応しません。キャプチャーはメモリ上で処理し、利用者が明示的に保存した小さな基準画像だけをローカルに残します。

`auto_visibility.py`は内部実験用の取り決めであり、安定した外部プラグインAPIではありません。判別器の`start()` / `observe()` / `stop()`と、セッションの`start()` / `tick()` / `stop()`を区別します。観測値は単調時計の時刻と`UNKNOWN` / `PLAYING` / `NOT_PLAYING`を渡します。既定ではプレイが0.2秒続くと選択項目を表示し、非プレイが0.3秒続くと非表示にします。不明または古い観測値も非表示の対象です。`stop()`は現在の表示状態を変えずに手動制御へ戻します。

OBSアダプターは、シーンUUID・シーン項目ID・ソースUUIDを確認した最上位の項目1–8個だけを制御します。元のキャプチャー項目は表示を維持し、制御対象から除外します。同じソースを複製したゲージも、名前や並び順ではなく別の項目IDで選択します。グループと入れ子のシーンは現在の対象外です。OBSリクエストは不可分な一括処理ではないため、失敗前に一部の項目が変わる場合があります。失敗時は適用状態を不明とし、自動制御を停止します。OBSへの接続が切れている間に非表示にできるとは保証しません。

キャプチャーと判別は、入力ポーリングとは別のワーカースレッドで実行します。OBSのパスワードと選択内容はデータフォルダーの `automation.json`、基準画像は `automation-template.png` に保存します。パスワードと画像は通常の設定応答・イベント・設定エクスポート・公開配布物には含めません。既定の `data/` はGitの対象外です。別のデータフォルダーを指定した場合もコミットしないでください。このファイルは暗号化されたパスワード保管庫ではありません。

アプリ起動時は毎回、自動化が停止しています。同じ項目を制御するAdvanced Scene Switcherなどのルールを先に止め、確認欄にチェックして明示的に開始します。切断やシーンコレクション変更で自動化は停止し、自動再接続・再試行・古い命令の再送は行いません。再接続し、対象を確認して保存してから開始してください。手動停止は現在の表示状態を維持します。

OBSを使わずにソースからポリシーを確認するには、次を実行します。

```sh
python tools/replay_visibility.py
```

合成した観測値と仮のOBS応答を使い、処理結果とリクエストをJSONL（1行にJSONオブジェクト1個）で出力します。画像認識や実際のOBS動作の検証ではありません。任意の引数として、観測値の配列を保存したJSONファイルを指定できます。

自動テスト、合成画像、実際のOBS操作、ゲームとの同時使用、パッケージ実行はそれぞれ別の根拠です。実施済みの検査と残る性能・復旧・配布検証は[検証状況](VALIDATION.ja.md)を参照してください。コードを接続したことだけで実環境の検証を代替しません。

BMSと外部プラグインローダーは実装していません。実際のユーザーのプレイヤー・スキン・入力方式と検証用資料が揃ってから実装範囲を決めます。判別器を追加するだけで、入力・レーン配置・スクロールまで互換になるわけではありません。

## 設計上の制約

- ネイティブ入力の取得を、ブラウザーのフォーカスから独立させます。
- 動きはフレーム数ではなく経過時間で計算します。オーバーレイの高さで速度が変わってはいけません。
- 保存する `manualOverlayHeight` と実際に適用する `overlayHeight` を分けます。自動モードではLIFTから高さを求めます。モードがない旧設定は、以前の手動高さを失わずに自動モードへ移行します。LIFT 0では入力ノーツの領域を表示しません。
- `getObsPlacement()` とOBS Luaの配置計算を一致させます。Xの基準は75/1413で固定し、YはLIFTと基準高さ723pxから求め、保存された整数の移動量を加えます。幅の変更や手動高さで基準位置を動かしてはいけません。2Pの基準位置は左右反転による推定であり、実際のキャプチャで確認した座標ではありません。
- 1080pの幅・比率プリセットは、ユーザーが明示的に操作した場合だけ適用します。ゲームの数値、プレイ位置、入力割り当て、手動高さを保持し、レーンのサイズとともに位置の移動量だけを初期化します。
- シーンの配置は、OBSで明示的に適用するか、ユーザーが変換を編集したときだけ変更します。アプリの位置を使う選択肢を追加するときも、既存スクリプトの手動X/Yを保持します。
- 実際の入力が表す意味を変えません。長押しだけで、譜面上のロングノーツかどうかは判断できません。
- ボタンの解放、軸の値の循環、デバイスの切断で、入力状態が押されたまま残らないようにします。
- 手動の割り当てを引き続き設定可能にします。案内付き設定では、特定コントローラーのボタンIDやスクラッチ軸の符号を前提にしません。`scratchInvert` によって、時計回りを `+1`、反時計回りを `-1` に正規化します。
- 値が循環する同じ軸で、時計回りと反時計回りをそれぞれ確認します。方向設定をやり直す場合は7鍵の割り当てを保持し、両方向のサンプルを消去します。案内はターンテーブルを上から見た方向で説明します。物理的な回転方向との対応は、この案内に従うことを前提とします。
- オーバーレイとプレビューの両方で、時計回り ↻ / 反時計回り ↺ の矢印と、淡い・濃いコーラル色を一致させます。隣り合うスクラッチ区間でも方向転換を見分けられるようにします。
- 案内付きの割り当ては結果の確認後に適用します。キャンセル、切断、デバイス変更時に未完成の設定を保存してはいけません。
- ループバックアドレスだけで待ち受け、設定はローカルに非公開で保存します。
- 無関係な連携、個人のパス、非公開のOBS設定を、公開ソースとWindows配布版の両方から除外します。
- 公開するOBS補助スクリプトはオーバーレイだけを起動します。同じフォルダーにある無関係なサービス用スクリプトを検索・起動してはいけません。
- 一般ユーザーの起動方法は1つの実行ファイルにまとめます。インストール手順にPython、pip、ターミナル操作を追加しません。

速度モデル、互換性の根拠、入力表示の制約は[技術リファレンス](REFERENCE.ja.md)を参照してください。

## Windowsアプリをビルドする

**Windows x64**でビルドします。公開Windowsビルドには、`tools/python-runtime.json` に固定された公式 **Python 3.13.16 x64** 配布版を使います。準備コマンドは既存のPython 3.10以降で実行できます。ソースの実行は引き続きPython 3.10以降に対応し、一般ユーザーにはZIPにランタイムを同梱します。

既存の `.venv-build` がない、クリーンなチェックアウトから始めてください。準備コマンドはpython.orgからPythonと対応するメタデータを取得し、固定されたハッシュを確認して `artifacts/python-runtime/` に展開します。システム全体へのPythonのインストール、PATH、レジストリ、ファイルの関連付けの変更は行いません。

```powershell
python tools/prepare_runtime.py
artifacts\python-runtime\python\python.exe -m venv .venv-build
.venv-build\Scripts\python -m pip install -r requirements-build.txt
.venv-build\Scripts\python tools\build_windows.py --require-verified-runtime
python tools/smoke_windows.py
```

Windows ZIPには `LiftTrace/` フォルダーがあり、`LiftTrace.exe`、`_internal/` の依存ファイル、OBSスクリプト、文書、第三者のライセンス表記が入っています。この構成を維持してください。ソースだけのアーカイブはPyInstallerなしで作成できます。

```sh
python tools/build_release.py
```

既定の出力先は `artifacts/` です。ソースのビルダーでは `--output-dir PATH` も指定できます。基本動作の検査スクリプトには、任意でZIPのパスを指定できます。最終ソースとバイナリを同じリビジョンから作成し、[リリースチェックリスト](RELEASING.ja.md)を確認してください。

ビルド中は、展開した `python/` フォルダーの隣に `artifacts/python-runtime/downloads/` を残してください。固定されたアーカイブ、公式Windowsマニフェスト、配布版の構成要素を示すSPDXソフトウェア部品表（SBOM）が入っています。ビルダーは展開した原本を公式ZIPと比較し、同梱するDLL/PYDをその原本と照合します。別のPythonから作成した仮想環境は再利用せず、新しいビルド環境を用意してください。

`--require-verified-runtime` はランタイムの出所を確認できない場合にビルドを停止します。通常の試作ビルドでは未確認の構成要素を記録できても、公開用の検証に合格したことにはなりません。完了した実行記録は[検証状況](VALIDATION.ja.md)を参照してください。ソースZIPにはPythonランタイムを同梱しません。

## 手動で確認する

現在の根拠、初めて使う方による確認手順、短い報告用テンプレートは[検証状況](VALIDATION.ja.md)を参照してください。観察した結果と予定している検査を区別します。AIレビューや合成入力だけでは、実際の回転方向、ゲームのタイミング、読者にとって自然な文章かどうかを確認できません。

UIを変更した場合は、新しく展開したWindows ZIPから使い方の手順を進め、言語選択、案内付き設定のキャンセル・適用、入力プレビュー、OBS用アドレスのコピー、設定の書き出し・読み込みを確認します。小さなデスクトップウィンドウはブラウザーと別に確認してください。よくある起動失敗からの復旧に、ターミナル操作を要求してはいけません。

タイミングを変更した場合は、短押し・長押し、同時押し、連打、両方向のスクラッチ、方向転換、切断、同じ速度で異なる2つの手動高さをテストします。黒・透明の背景と1P/2Pの配置も確認します。LIFT 401で自動高さが290になること、モード変更で手動高さが保持されること、LIFT 0で自動の入力ノーツ領域が表示されないこと、旧設定の移行で指定値を失わないことも確認します。合成デモを目視する前に、正のLIFT値か手動高さを設定してください。

位置を変更した場合は、1P/2P、LIFT 0/401/999、正負の移動量を確認し、幅・手動高さ・緑数字・SUDDEN+の変更では基準位置が変わらないことを確認します。1080pプリセットが入力割り当てとゲームの数値を保持し、移動量を初期化することも確認します。ブラウザーソースのプロパティでの幅・高さのコピーと、「変換の編集」でのX/Yのコピーは別々に確認します。OBS Luaでは、新しいアプリ位置の既定値、旧手動位置の移行、アプリ・手動によるサイズと位置のすべての組み合わせをテストします。配置の適用時は、左上揃え、100%のサイズ、境界に合わせる拡縮なし、クロップ0を使います。アプリUIの設定変更だけでOBSシーンが移動してはいけません。

起動・終了処理を変更した場合は、新しい単独サーバーと、管理ウィンドウを閉じても残る必要がある既存サーバーをテストします。サーバーがない状態でOBSが起動し、OBS終了時に停止することを確認した後、既存の単独サーバーは終了せずに残ることも確認します。パッケージ版EXEの選択とソースPythonへの切り替えの両方を確認してください。この確認のために配信や録画を開始する必要はありません。

コントローラー処理を変更した場合は、軸の極性が逆になる両方の場合で、時計回り、反時計回りの順に設定を最後まで進めます。同じ方向の入力の拒否、複数の軸候補、値の循環、再試行、キャンセル、再読み込み、表示ノーツの方向転換を確認します。機種、モード、Windows上の軸・ボタン情報、実際にテストした内容を記録してください。通常のデバイス入力確認と、INFINITASとの同時利用・キャプチャのタイミング確認は区別します。パッケージの自動基本動作検査は仮の親プロセスを使うため、実際のOBSや機器を使った検査の代わりにはなりません。

## ライセンスと配布ファイルの管理

プロジェクトのコードはMITライセンスです。Python、Tcl/Tk、再配布するPyInstallerの構成要素、その他の同梱ランタイムには、それぞれの条件が適用されます。Windowsビルダーが集めた表記を確認し、実行ファイル全体がMITライセンスのみで配布されるとは説明しないでください。

ランタイムの固定情報は、取得した配布版を公式マニフェスト・SBOMに結び付けます。バイナリの比較は、同梱ランタイムがその配布版のものと一致することを確認します。ライセンス表記の収集にも、対応する構成要素の情報を使います。パッケージにはSBOMを `provenance/python-runtime.spdx.json` として保存し、出所URL、ハッシュ、バイナリの対応関係を `MANIFEST.json` に記録します。上流のSBOMには他のプラットフォームのツールや依存関係も含まれるため、その全パッケージ一覧がLift Traceの同梱物一覧ではありません。

`bundledRuntime.runtimeProvenanceVerified` は、公式配布元まで追跡できることを記録します。独立したビルド再現、セキュリティ監査、法的な認証を意味しません。一致を裏付ける根拠が得られるまで、未確認の構成要素をマニフェストに残してください。通常のビルドやCIアーティファクトの作成に成功しても、公開用の検証の代わりにはなりません。

配布ランタイムを変更する場合は、`tools/python-runtime.json` を更新する前に、新しい公式アーカイブ、マニフェスト、SBOMを併せて確認します。新しいランタイム用フォルダーとビルド環境で、出所とパッケージの検査をやり直し、検証記録を更新してください。ダウンロードを通すためだけに、照合に失敗したハッシュを新たに計算した値へ置き換えてはいけません。

配布用ビルダーは、ファイル一覧を明示して使用します。チェックアウト全体の再帰コピーに置き換えないでください。`data/`、ログ、キャッシュ、仮想環境、ユーザー設定、個人のパス、OBSプロファイル、認証情報、ゲームファイルとキャプチャは除外します。新しい公開文書やテストは、対応する許可リストに追加する必要があります。
