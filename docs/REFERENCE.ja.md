## 配布物の構成と範囲

Windows ZIP には、起動用ウィンドウ、Python ランタイムとアプリの実行に必要なファイル、同梱ランタイムのライセンス情報、公開ドキュメント、任意で使える OBS Lua/PowerShell 連携が含まれます。ソース ZIP には同じプロジェクトのソースコード、テスト、ビルドツールが含まれ、インストール済みの Python ランタイムは含まれません。

どちらの配布物にも、iPad リモートサーバー、配信環境をまとめて起動するツール、個人のコントローラー設定、特定の PC のパス、OBS プロファイル、ゲームの実行ファイル、楽曲、ゲーム画像は含まれません。使い方の図は、このプロジェクトで制作したものです。

公開版の OBS 起動ヘルパーが起動するのは Lift Trace のオーバーレイだけです。アプリの隣にある別サービスの起動スクリプトを探したり、実行したりしません。

アプリは、同じ PC 内で使う HTTP サーバーと OBS のブラウザソースで構成されています。OBS 用のネイティブ DLL プラグインではありません。設定画面のアドレスは `http://127.0.0.1:8765/`、オーバーレイの出力先は `http://127.0.0.1:8765/overlay.html` です。ブラウザでの描画とネイティブ入力の取得は分かれているため、設定タブを閉じてもデバイスの入力は引き続き届きます。

## 落下速度の計算

**1920 × 1080 の OBS キャンバスにゲームを全画面で表示**し、ブラウザソースの**変換の拡大率が 100%**であることを前提にしています。

```text
1080p 基準のレーン高さ = 723 px
見えているレーンの高さ ≈ 723 × (1000 − LIFT − SUDDEN) / 1000
ノーツが見えている時間 ≈ 緑数字 / 600 秒
速度 (px/s) = 見えているレーンの高さ × 600 / 緑数字 × 速度補正値
```

LIFT + SUDDEN は 1000 未満にする必要があります。たとえば LIFT 200、SUDDEN 300、緑数字 300、補正値 1 なら 723 px/s です。オーバーレイの高さを 120 px から 360 px に変えても速度は変わらず、より長い範囲の入力を表示します。

これは表示を合わせるための近似式です。ゲームの公式 API ではなく、ゲーム内のピクセル丸め処理をすべて正確に再現するものでもありません。基準の高さは 1920 × 1080 のキャプチャと照合しました。表示遅延は入力ノーツが現れる時点をずらし、速度補正は落下速度を変えます。二つの設定は役割が異なります。

オーバーレイのサイズとクロップは、表示する範囲を決めます。OBS で縦方向の拡大率を変えると、見かけの落下速度も変わります。横方向のレーン幅と 1P/2P の配置は、横の位置合わせにだけ影響します。

アプリはゲームから緑数字、LIFT、SUDDEN、BPM を読み取りません。実際のゲーム速度が変わっても自動では追従しません。初期値は緑数字 300、LIFT 0、SUDDEN 0 です。プレイヤーに推奨するゲーム設定ではありません。

計算方法は、[KONAMI の速度オプションの説明](https://p.eagate.573.jp/game/2dx/26/howto/play/option_speed.html)と [masaoblue 氏の INFINITAS シミュレーターの分析](https://note.com/masaoblue/n/n02ecb7426a76)を参考にしています。

## 表示高さの自動計算と手動設定

実際に出力する高さと、保存済みの手動高さを別々に管理します。

```text
heightMode = "auto"（初期値）または "manual"
自動高さ = max(1, round(723 × LIFT / 1000)) px
manualOverlayHeight = 保存済みの手動高さ、40–2160 px
overlayHeight = 選んだモードから算出した実際の出力高さ
```

LIFT 401 なら自動高さは 290 px です。速度計算と同じ 1080p レーンの近似値を使っており、キャプチャしたゲーム画面の寸法を直接測定するわけではありません。幅は変更でき、既存設定との互換性のため初期値の 400 px を維持しています。**1080p のレーンサイズに合わせる**を押すと、基準値の 432 px になります。既存設定に自動適用されることはありません。

自動モードで LIFT が 0 の場合、入力を表示する空間がありません。内部の 1 px キャンバスは技術上必要な透明の空領域であり、推奨する表示高さではありません。画面では、入力ノーツの落下を確認する前にゲームの LIFT を入力するか、手動高さを選ぶよう案内します。

新しい設定と、`heightMode` がないリリース前の設定は自動モードになります。以前の `overlayHeight`、またはさらに古い `liftHeight` の値は `manualOverlayHeight` に保存します。以前の手動値がなければ 240 px を使います。この代替値は、通常の自動設定で 240 を入力するという意味ではありません。モードを切り替えても手動値は保持されます。`overlayHeight` は計算結果なので、コードから手動高さを変える場合は、この結果を上書きせず `manualOverlayHeight` を変更してください。

表示高さのモードや手動高さだけを変えても、速度は維持されます。LIFT 自体を変えるとゲームで見えるレーンの長さが変わるため、自動高さと速度の計算値が両方変わります。

設定ページとオーバーレイは高さを再計算しますが、**すでに追加した OBS ブラウザソースのサイズは自動では変わりません。** 新しい高さをブラウザソースのプロパティにコピーするか、任意の OBS スクリプトで配置を適用してください。縦方向の拡大率を変える方法では代用できません。

## OBS の位置と 1080p サイズ合わせ

`getObsPlacement()` は、1920 × 1080 キャンバス上でのソースの左上座標を返します。配置は左上、拡大率は 100%、境界ボックスによる拡大縮小なし、クロップは 0 を使います。

```text
基準レーン幅 = 432 px
1P X = 75 + obsOffsetX
2P X = (1920 - 75 - 432) + obsOffsetX = 1413 + obsOffsetX
Y = 723 - round(723 × LIFT / 1000) + obsOffsetY
```

たとえば LIFT 401 で位置補正がなければ、Y は 433、自動高さは 290 です。X は 1P で 75、2P で 1413 です。1P の基準は 1080p 全画面キャプチャと照合しました。2P はそれを左右対称にした推定値で、実際の 2P キャプチャで測定した値ではありません。ゲーム画面の構造が異なる場合や、キャプチャを拡大・縮小・クロップしている場合は位置補正が必要です。

`obsOffsetX` と `obsOffsetY` は整数ピクセル単位の位置補正値で、初期値は 0 です。X が正なら右へ、Y が正なら下へ移動します。指定できる範囲はそれぞれ −3840…3840、−2160…2160 です。位置はゲームのレーン基準に固定され、任意の出力幅、手動高さ、緑数字、SUDDEN+ には依存しません。LIFT は Y を、1P/2P は X を変えます。幅を変えてもソースの中心位置を合わせ直すことはありません。

**1080p のレーンサイズに合わせる**は、`width = 432`、`scratchWidth = 5/3`、`blackKeyRatio = 7/9` を設定し、二つの位置補正値を 0 にします。ゲームの数値、選択したプレイ位置、入力割り当て、高さモード、保存済みの手動高さは維持します。この幅の比率では、スクラッチレーンが 90 px、白鍵レーンが 54 px、黒鍵レーンが 42 px になります。ユーザーが明示的に実行する設定であり、既存ユーザーに自動適用される変更ではありません。

設定ページには X と Y を個別にコピーするボタンがあります。設定を変えても計算値が更新されるだけで、**既存の OBS シーン内のソースは移動しません。** 変換の編集に X/Y を貼り付けるか、OBS スクリプトで配置を適用してください。LIFT を変えた場合、自動高さモードではブラウザソースの高さと Y 位置の両方を更新する必要があります。手動高さだけを変えた場合は、高さだけを更新します。

## 入力ノーツが表すもの

次の表は初期設定での表示です。開発版では、下記の表示設定で鍵盤入力の見た目だけを変更できます。

| 入力 | 表示 |
| --- | --- |
| 鍵盤を短く押す | 押した時間に応じた長さの入力ノーツが落下します。 |
| 鍵盤を押し続ける | 押している間はノーツの胴体が伸びます。離すと末尾も判定ラインから離れて落下します。 |
| 時計回りの回転 | ↻ と明るいコーラル色（`#ffb4aa`）で表示します。長さは検出した回転時間に応じて変わります。 |
| 反時計回りの回転 | ↺ と濃いコーラル色（`#e45470`）で表示します。方向が変わると新しい区間が始まります。 |
| デバイスの切断 | 押し続けた状態が残らないよう、有効な入力状態を解除します。 |

長押しはロングノーツのように見えることがありますが、アプリには譜面に実際のロングノーツがあるかどうかはわかりません。連続した回転の中にある個々のスクラッチノーツを区別したり、譜面情報からロングスクラッチを識別したり、ゲームの判定を表示したりすることはできません。スクラッチの停止は、短い待ち時間が過ぎた後に推定します。入力ノーツは、譜面ではなくコントローラーの入力記録を表します。

ネイティブ入力は約 4 ms 間隔で読み取ることを目標にしています。描画はブラウザのアニメーションフレームに従い、任意の OBS スクリプトはブラウザソースを 60 FPS に設定します。実際の結果は、OBS の出力フレームレート、処理の実行タイミング、ドライバー、キャプチャ遅延の影響を受けます。合成デモが滑らかに見えるだけでは、実際のキャプチャとの同期が確認できたことにはなりません。

### 鍵盤入力の胴体と短い入力の表示（未リリース）

| 設定 | 初期値・範囲 | 動作 |
| --- | --- | --- |
| `inputBodyEnabled` | `true`・真偽値 | `false`では1–7鍵の頭だけを表示し、胴体と末尾を描きません。 |
| `shortInputEnabled` | `false`・真偽値 | 胴体が有効なとき、短い入力の表示の長さを縮めます。 |
| `shortInputThresholdMs` | `200`・整数1–2000ms | 離した入力の実際の継続時間がこの値未満の場合だけ縮めます。 |
| `shortInputPercent` | `30`・整数1–100% | 元の表示の長さから残す割合です。100%では元の長さを維持します。 |

頭だけの表示は、入力の長さに関係なく、押している鍵盤と離した鍵盤の両方に適用します。押し始めに生じた頭1つが元の位置・速度・表示遅延に従って移動し、押し続けても新しい頭を繰り返し生成しません。胴体をオフにしても短い入力の設定は保持します。スクラッチの長さと矢印、プレビュー上部の例示用ゲーム譜面は変更しません。

胴体が有効な場合、短縮は表示遅延を考慮して画面上でも離した状態になった入力だけに適用します。基準時間以上の入力と、まだ押している表示の入力は元の長さを保ちます。描画だけの変更であり、入力の開始・終了時刻、入力記録、エンジンの元の区間は変更しません。譜面のロングノーツを判別する機能ではありません。

設定画面の比較は未保存の変更内容を表示します。**適用して保存**で実際のオーバーレイとローカル設定に反映し、**変更を戻す**で適用済みの値に戻します。新しい設定項目がない以前のファイルは胴体オン・短縮オフで読み込み、従来の表示を維持します。

## コントローラーの対応範囲と初期設定

Windows のネイティブ入力は、WinMM でジョイスティックを列挙して入力を読み取ります。ボタン番号は 0 から始まります。スクラッチは、**端の値まで進むと反対側の端へ戻る絶対位置の軸**を前提にしています。対応する軸の名前や番号はデバイスによって異なります。キーボード専用モードや別の形式のスクラッチ信号には、別の入力アダプターが必要になる場合があります。

初期設定では各鍵盤に重複しないボタンを一つずつ割り当て、次の鍵盤へ進む前にボタンを離す必要があります。その後、ターンテーブルを上から見て時計回り、反時計回りの順に回すよう案内し、両方向を別々に確認します。二つの手順で同じ循環する軸が検出され、移動の符号が逆になる必要があります。時計回りの入力に応じて `scratchInvert` を保存し、適用後は `+1` が時計回り、`-1` が反時計回りを表します。デバイスの軸の符号だけで物理的な回転方向が決まるわけではありません。ユーザーが両方向の案内に従う必要があり、二つとも逆方向に解釈した場合、アプリはそれを検出できません。

結果を確認して適用すると、通常の入力割り当て設定が更新されます。キャンセルすると、途中の割り当ては保存しません。デバイスの変更や切断があると、進行中の設定は無効になります。回転方向の設定をやり直しても、七つの鍵盤の割り当ては維持し、両方向だけを再確認します。自動検出が合わない場合や問題を調べる場合は、方向反転を含む手動設定を使えます。

開発中に PHOENIXWAN 一台で、七つの鍵盤と双方向の X 軸スクラッチ入力を確認しました。この基本入力の確認だけで、現在の初期設定の全手順や、すべてのファームウェア・モード・デバイスとの互換性が検証されたわけではありません。INFINITAS との同時入力やゲームキャプチャとの正確な同期は、各環境で確認する必要があります。記録済みの範囲は[検証状況](VALIDATION.ja.md)を参照してください。入力アダプターは入力の読み取りだけを行い、ドライバーのインストール、コントローラーのファームウェア変更、ゲームへの入力送信は行いません。

アプリを手動で起動する場合、以前選択したデバイスを自動では復元しません。OBS 起動ヘルパーは設定済みのデバイス番号を選択でき、初期値は 0 です。-1 なら自動選択を省略します。デバイスを接続し直すと、番号が変わる場合があります。

macOS/Linux では、ソースからデモを実行し、設定ページにフォーカスがある状態でキーボード入力を使えます。Windows のネイティブ入力と OBS 自動起動は対応していません。実行ファイルとして配布するデスクトップアプリは Windows x64 専用です。

## 任意の設定：OBS 自動起動

使い方では、初期値を使った最小限の自動起動手順を案内しています。以下は、設定の変更やトラブル調査のための詳細です。

1. 単独で起動しているアプリを終了してから、**OBS → ツール → スクリプト → +** でアプリフォルダー内の `obs-lift-trace.lua` を選びます。
2. Lua ファイル、`start-obs-bridge.ps1`、`LiftTrace.exe` は同じフォルダーに置きます。ヘルパーは隣にある実行ファイルを優先します。実行ファイルを使わずソースから動かす場合は、Python のパスを空欄にして自動検出させるか、使うインタープリターを指定できます。OBS の Python スクリプト設定は使いません。
3. ローカルポートの初期値は 8765 です。変更する場合は、アプリとブラウザソース URL のポートも同じにする必要があります。アドレスをコピーするためにこの値を変える必要はありません。通常の設定画面にコピーボタンがあります。
4. コントローラー ID の初期値は 0 で、-1 にすると自動選択を無効にします。別のコントローラーを使う場合は、設定ページに表示される番号を入力してください。デバイスを接続し直すと、番号が変わる場合があります。
5. **入力サーバーを起動 / 接続**は、今回の OBS 起動で使うローカルサーバーを起動または再利用します。**入力設定を開く**は、ブラウザで設定画面を開きます。
6. **Lift Traceで設定したサイズを使う（おすすめ）**は初期状態で有効です。**オーバーレイを追加 / 配置を適用**を押すと、保存済みの幅と自動・手動モードで決まる実際の高さを読み取り、指定した名前のブラウザソースを 60 FPS で作成または更新します。この項目を無効にすると、スクリプトにある個別の幅・高さの値を使います。
7. **Lift Traceで計算した位置を使う（おすすめ）**を有効にすると、**オーバーレイを追加 / 配置を適用**を押したときに、保存済みの 1P/2P、LIFT、位置補正値から X/Y を計算します。無効にすると、スクリプトの手動 X/Y 値を使います。新しいスクリプト設定では初期状態で有効です。リリース前の設定に手動座標が保存されている場合、この項目を明示的に有効にするまでは手動の位置を維持します。

配置の適用は、現在のシーン内にある指定した名前のソースを変更します。他のソースより前面に移動し、拡大率を 100%、配置を左上、境界ボックスによる拡大縮小をなしに設定して、クロップを解除し、ソースをロックします。選んだアプリ計算値または手動位置モードの X/Y を適用します。配信や録画は開始しません。その後アプリで設定を変えても、この操作が自動実行されたり、ブラウザソースのサイズ・位置が変わったりすることはありません。ソースのプロパティと変換の値を直接更新するか、もう一度配置を適用してください。

スクリプトはシーンコレクションに属します。必要なシーンコレクションごとに登録し、アプリフォルダーを移動した場合は登録したパスも変更してください。スクリプトの削除や自動起動の無効化は、次回以降の起動に反映されます。すでに起動したサーバーには、以下の終了規則が引き続き適用されます。

失敗した場合は、`data/obs-bridge-*.status`、`data/obs-bridge-*.stdout.log`、`data/obs-bridge-*.stderr.log` を確認してください。コントローラーの選択に関する問題は `data/obs-controller-*.log` に記録されます。デスクトップの起動ウィンドウの診断ログは `data/lift-trace.log` で、アプリフォルダーに保存できない場合は `%TEMP%/LiftTrace/` を使うことがあります。ログを共有する前に、個人のパスやデバイス情報を削除してください。

## サーバーを終了する側

| 起動時の状況 | サーバーの終了方法 |
| --- | --- |
| LiftTrace.exe が新しいサーバーを起動した場合 | 起動ウィンドウを閉じるか終了を選ぶと、そのサーバーを終了します。 |
| LiftTrace.exe が起動済みの Lift Trace サーバーに接続した場合 | 起動ウィンドウを閉じても、既存のサーバーは動き続けます。 |
| OBS 起動ヘルパーが新しいサーバーを起動した場合 | その OBS プロセスが終了すると、サーバーも終了します。 |
| OBS 起動ヘルパーが正常に動作しているサーバーを見つけた場合 | 既存サーバーの終了は引き受けずに再利用します。OBS が終了しても、サーバーは動き続けます。 |

自動起動設定の変更や OBS スクリプトの削除は、次回以降の起動に反映されます。OBS がすでに起動したサーバーは、その OBS プロセスの終了に引き続き連動します。同じポートを使っているという理由だけで、無関係のプロセスを終了してはいけません。

## 設定とプライバシー

既定の `data/` フォルダーは、展開したアプリまたはソースのフォルダー内にあります。`settings.json` はオーバーレイの設定、`desktop.json` はデスクトップの起動ウィンドウの言語を保存します。実行中に記録する診断情報には、ローカルのパスやデバイス情報が含まれる場合があります。

アプリは `127.0.0.1` でのみ待ち受け、通常の利用にアカウントや外部サービスへの接続は必要ありません。同じ PC の OBS とブラウザで使うことを想定しています。外部からアクセスできる公開ネットワークサービスとして公開しないでください。診断情報を共有する前に[セキュリティ案内](../SECURITY.ja.md)を確認してください。
